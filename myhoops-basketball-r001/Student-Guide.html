Start with one small win

Your site can be about a team, a style, a hobby, a business idea, food, games, or something else you care about. Today’s first win is changing one heading and seeing it appear in the browser.

You do not need to memorize the code. Find the named section, change one thing, save, and check what happened. Keep earlier planning work and art; reuse it.

Your daily loop

Open → Change one thing → Save → Refresh → Check → Upload → Log

Begin coding when your teacher has cleared your project readiness checks. While waiting, choose your page words, sketch an idea, write an art prompt, or explain your plan aloud.

Open the project log master only when your teacher gives you your own copy. Your teacher will provide the live Google Sheet link. Do not edit another student’s log.

Find the right files

Your shared Google Drive course folder is the saved class copy. The folder on the Windows computer is your working copy. The public website is a teacher-published copy. Saving one does not automatically update the others.

Your teacher chooses a short project name such as court-stories. Use lowercase letters, numbers and hyphens in filenames. Use r001, then r002, to identify saved revisions. Never name a file “final final.”

Keep the log, grades and private notes outside the website ZIP. They do not belong on the public site.

Open your project on Windows

  1. Open your own shared WEB folder and Project Log. On Assignments, find your next task and its evidence request.
  2. On Start, find Latest working ZIP. Open that exact Drive link and download it. Do not guess from a list of similar names.
  3. In Windows File Explorer, right-click the ZIP → Extract All. Choose an easy-to-find folder in Downloads. Open the extracted folder until you see index.html inside site.
  4. Open vscode.dev in Chrome or Edge. Choose Open Folder, then the extracted site folder. Allow access to that folder when asked. No GitHub account is needed for this local-folder routine.
  5. Click index.html in the editor’s left file list. Separately, double-click that same file in File Explorer to open its browser preview.
  6. Put the editor and preview side by side. Check that the preview address points to the same extracted folder.

If Open Folder or saving is blocked, stop and ask your teacher. The fallback is teacher-approved desktop VS Code opening the same local folder. Do not install software or connect a different cloud editor on your own.

Drive’s web preview is not the running website. Do not convert HTML/CSS files into Google Docs. Never edit inside the unopened ZIP.

Make your first personal change

  1. In index.html, find the comment STUDENT EDIT: HERO.
  2. Replace MyHoops Basketball between the h1 tags with your own title. Keep the tags.
  3. Press Ctrl+S. Click the preview window and press Ctrl+R.
  4. Point to the changed title. If it did not change, check your folder, file and Save step before editing more code.
  5. Change the sentence below the title to explain who your site helps and what visitors can do.
  6. In styles.css, change one color under STUDENT EDIT: THEME. Keep text easy to read. Save and refresh again.

Choose one next challenge: make a team profile card, describe a signature hairstyle, write a menu item, or introduce a game character. You choose the subject; the same HTML skills apply.

Ask AI for one small explanation: “Explain what this CSS rule changes. Show one edit and how I can test it. Keep my filenames and navigation.” Read and test any suggested change before keeping it.

Save back to Drive before leaving

  1. Save every changed file. Test your three page links and return Home. Check your change and take one useful screenshot if the task requests it.
  2. In File Explorer, go up one level so you can see the site folder. Right-click it → Compress to ZIP file, or Send to → Compressed (zipped) folder on older Windows.
  3. Name the ZIP with the next revision, such as court-stories-r002.zip. Do not overwrite the previous ZIP.
  4. In Drive, open Production → Working. Choose New → File upload and upload the ZIP. Wait for the upload to finish.
  5. Open the uploaded ZIP preview and check its name and files. Download it to a separate verification folder, extract it, and open its site/index.html. Confirm your latest change is present. This proves the Drive copy contains your work.
  6. In Versions, add the revision, date, changed files, reason, test result and Drive link. Update Latest working ZIP and Current revision on Start.
  7. Update the assignment status and evidence link. If it is ready, choose Ready for review. Tell your teacher if upload or verification failed before signing out.

Next class—even on a different computer—start from the recorded Drive ZIP. Local Downloads may be cleared. Use one working folder at a time; do not combine two different revisions without help.

HTML you will use

HTML names the content. Most elements have an opening tag, content and a closing tag. An attribute adds information inside an opening tag.

<h1>My basketball story</h1>
<a href="skills.html">Meet the team</a>
CodeWhat it doesTry and check
<!doctype html> / <html lang="en">Starts a modern HTML document and identifies the language.Keep these in the starter.
<head>, <title>, <meta>Page information; title labels the browser tab.Change the title and check the tab.
<body>All visible page content.Keep your page sections inside it.
<header>, <nav>, <main>, <section>, <footer>Meaningful regions; nav holds page links.Keep one main region and label your sections with headings.
<h1>, <h2>, <h3>Heading levels; use one main h1 in this starter.Use h2 for sections, not just bigger text.
<p>, <strong>, <em>Paragraph, important text and emphasis.Replace one paragraph with your own words.
<a href="about.html">About</a>A link opens another page or location.Click it; check the spelling and Home return.
<img src="assets/team.png" alt="Team warming up">Displays an image; alt describes its meaning.Use your real file and useful description. Decorative images can use alt="".
<ul>, <ol>, <li>Unordered list, ordered steps and list items.Create a list with three items.
<figure>, <figcaption>Pairs an image with a visible caption.Add source credit where needed.
<div class="card">A generic grouping when no semantic element fits.Use the existing card class for a content block.
<button type="button">An action control, usually needing JavaScript.Use a link for navigation; a button alone does not save or send anything.
<label>, <input>, <textarea>, <form>Form structure and fields.A form needs an approved destination/backend to send information.
<!-- a note -->HTML comment; invisible on the page.Comments are visible in source; never put secrets here.

Add your own image

<!-- Put your image file in site/assets first. -->
<figure>
  <img src="assets/team.png"
       alt="Five players practicing passing on a court">
  <figcaption>Practice day. Image credit: add your source.</figcaption>
</figure>

Change the path to your actual filename. Match capitalization: team.png and Team.PNG may behave differently on the host. A Google Drive sharing link is not a dependable image-file path.

CSS you will use

CSS changes appearance. A selector chooses an element; declarations inside braces set its properties. A class selector begins with a dot.

.card {
  background: #ffffff;
  color: #203149;
  padding: 1.25rem;
  border-radius: 1rem;
}

The box model

Content sits inside padding, then a border, then outer margin. The starter uses box-sizing: border-box to make sizing more predictable.

If a style does nothing, check the class spelling, closing brace, semicolon and the link to styles.css. Keep the CSS in that file rather than pasting it into the page text.

Test and recover

  1. Open Home, Skills and About; follow every link and return Home.
  2. Make the browser narrow. Check text, images and navigation without sideways scrolling.
  3. Press Tab through the links. You should see where you are. Press Enter to follow a link.
  4. Check meaningful image descriptions, readable colors and useful link text.
  5. If something breaks: press Ctrl+Z for your last edit, save and refresh. If still broken, keep the broken revision as evidence and ask for the last working ZIP.
  6. In Bugs, write: “On r002, open Explore, click Home. Expected Home page. Actual file not found. Tried correcting index.html. Retest passed.”

After about three minutes stuck, record the problem in Help and ask. Your next step can be a smaller task. Asking for help, finding a bug and explaining a fix are useful evidence—not a reason to give up.

  <h2 id="account-heading">Client account idea</h2>
  <p>Demo only. Accounts are not connected yet.</p>
  <button type="button" disabled>Sign-in demo unavailable</button>

Do not paste API secrets, passwords, tokens or real client details into HTML, the asset log or an AI prompt. The teacher will build the real account integration separately when the project is ready. Google’s server verification guide explains the security step.

Review and publishing

Ready for review means “I tested it and want feedback.” It does not mean your site is already public. Your teacher opens the exact submitted revision, checks the files, gives feedback and publishes an approved copy.

A possible address is https://studentsite.aeonsmash.com/web/your-project/. This is a proposed address, not a working link yet. Your actual preview URL will appear on Start after hosting is configured.

Use a project nickname publicly. Keep full names, school IDs, grades, private Drive links and client information out of the website. The project log stays shared only with the approved class participants.

When a preview link is provided, open all pages there and repeat your tests. Record the published revision in Versions. A successful upload does not prove the site works.

GitHub later

GitHub can keep code history and make collaboration easier. We will start it only after you can edit, save, test and recover your site reliably.

  1. Your teacher checks school access and account requirements, then helps set up one project repository with the intended visibility.
  2. Import your last approved site. Keep private logs and grades out of the repository.
  3. Open the repository in the browser editor. Make one change; review exactly which files changed.
  4. Commit with a message such as “Add menu descriptions.” Open github.com and verify the commit is present.
  5. Request review. Your teacher approves the release to the classroom site. A commit alone does not set your website address.

After the switch, the repository becomes the code source of truth. Drive keeps release ZIPs, evidence and your log. We will not edit both copies independently. GitHub’s browser editor guide explains commits and browser storage.
